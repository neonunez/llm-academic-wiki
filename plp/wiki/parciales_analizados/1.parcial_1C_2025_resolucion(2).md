## Parte 1 - Preguntas Teóricas

### Enunciado y Resolución
1. **¿La siguiente definición utiliza recursión explícita?**
   ```haskell
   esHoja :: AB a -> Bool
   esHoja Nil = False
   esHoja (Bin i r d) = esNil i && esNil d
     where esNil Nil = True
           esNil _ = False
   ```
   **Respuesta:** No, pues no es una función recursiva. No hay ningún llamado a sí misma.

2. **Indicar el tipo del esquema de recursión estructural `foldABNV`:**
   **Respuesta:** `foldABNV :: (a -> b) -> (a -> b -> b) -> (b -> a -> b -> b) -> ABNV a -> b`

3. **¿Qué tipo de recursión utiliza `listasQueSuman`?**
   ```haskell
   listasQueSuman :: Int -> [[Int]]
   listasQueSuman 0 = [[]]
   listasQueSuman n | n > 0 = [x : xs | x <- [1..n], xs <- listasQueSuman (n-x)]
   ```
   **Respuesta:** Recursión Global. El llamado recursivo no se realiza estrictamente sobre el predecesor estructural inmediato (`n-1`), sino sobre cualquier valor `n-x` calculado.

4. **División de casos justificada por Lema de Generación en `AB a`:**
   **Respuesta:** El árbol binario `t` puede ser: `Nil` o `Bin i r d` (con `r::a` y `i,d::AB a`).

5. **Predicado unario P para demostración por inducción estructural:**
   Propiedad: `forall xs::[a] . forall ys::[a] . length (entrelazar xs ys) = length xs + length ys`
   **Respuesta:** `P(xs) = forall ys::[a] . length (entrelazar xs ys) = length xs + length ys`

6. **Error al aplicar paso de deducción natural de `¬P v Q` a `¬P v Q |- Q v (P => Q)` mediante `vI1`:**
   **Respuesta:** El juicio en la premisa no es derivable, ya que desde `¬P v Q` no se puede deducir la conclusión directamente sin abrir casos.

7. **Reducción en un paso de `if isZero(zero) then Pred(Succ(zero)) else zero`:**
   **Respuesta:** Reduce a `if true then Pred(Succ(zero)) else zero` mediante las reglas combinadas de evaluación de la condición (`E-If` + `E-isZero0`).

8. **Error en regla de cómputo para foldr:**
   `foldr V1 :: V2 base ~> M; rec(h,r) ~> N -> N`
   **Respuesta:** Las variables `h` y `r` están libres en `N` y deben ser instanciadas/ligadas explícitamente para asegurar progreso (mediante sustitución explícita en `N`).

### Explicación y Análisis
- **Recursión Global:** Es crucial entender la diferencia con recursión estructural o sobre enteros (primitiva). En `listasQueSuman` la recursión salta a valores arbitrariamente menores, lo cual requiere garantizar la terminación por un buen orden, clasificándose como global.
- **Predicado Unario:** Para hacer inducción en listas o árboles cuando hay más de un parámetro, el cuantificador universal del *segundo* parámetro debe quedar "adentro" del predicado de inducción `P`, para fortalecer la hipótesis inductiva.

## Parte 2 - Ejercicios Prácticos

*(El desarrollo de la Parte 2 es idéntico en su estructura al analizado en `1.parcial_1C_2025_resolucion(1)`. A continuación se resaltan únicamente las variaciones de implementación interesantes de esta resolución).*

### Ejercicio 1 - Programación Funcional
**Variación en `reemplazarUno`:**
El alumno ITTIG propuso una resolución análoga para `reemplazarUno`, pero usando guardas anidadas explícitas con `if/else`:
```haskell
reemplazarUno :: Eq a => a -> a -> ABNV a -> ABNV a
reemplazarUno x y = recABNV
  (\k -> if k == x then Hoja y else Hoja k)
  (\k t' rec -> if k == x then Uni y t' else Uni k rec)
  (\i reci k d recd -> 
    if k == x 
      then Bi i y d
      else if elemABNV x i 
        then Bi reci k d
        else Bi i k recd)
```
**Análisis:** Es matemáticamente equivalente y perfectamente válido. Evalúa perezosamente `elemABNV` solo si la raíz `k` no era igual a `x`.

### Ejercicio 2a - Demostración de Propiedades
**Variación en Inducción:**
ITTIG fue mucho más exhaustivo al definir su Hipótesis Inductiva, usando expresamente la macro `P(t)` y declarando:
`P(i) = forall x,f . elemAB x i => elemAB (f x) (mapAB f i)`
Al llegar al Lema de Generación de Bools, iteró ordenadamente los tres casos provistos por el antecedente `True`. La estructura metodológica de esta demostración es un excelente modelo de respuesta para un examen.

### Ejercicio 3 - Cálculo Lambda Tipado
**Variación en Reducción Paso a Paso:**
Al reducir `head< ( ((\x:Nat. 2) zero) ::< 1 ::< []<Nat )`, el alumno detalló exhaustivamente el árbol de derivación de semántica operacional en línea:
`-> if 2 < head<(1 ::< []<Nat) then 2 else head<(1 ::< []<Nat)`
`-> if False then 2 else head<(1 ::< []<Nat)`
`-> head<(1 ::< []<Nat)`
`-> 1`
Este grado de formalidad en el paso a paso previno errores comunes de reducción anticipada.

### Chuleta
- **Precisión en Inducción:** Definir el predicado `P(t)` separando el `forall` estructural (el que se quita al asumir el elemento) de los `forall` internos (los que quedan en la hipótesis inductiva) es la clave para no equivocarse al aplicar la HI sobre ramas como subárboles.
