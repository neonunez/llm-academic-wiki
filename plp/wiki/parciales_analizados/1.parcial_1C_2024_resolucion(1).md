## Ejercicio 1 - Programación Funcional

### Enunciado
Aclaración: en este ejercicio no está permitido utilizar recursión explícita, a menos que se indique lo contrario.

El siguiente tipo de datos sirve para representar árboles ternarios:
```haskell
data AT a = NilT | Tri a (AT a) (AT a) (AT a)
```

Definimos el siguiente árbol para los ejemplos:
```haskell
at1 = Tri 1 (Tri 2 NilT NilT NilT) (Tri 3 (Tri 4 NilT NilT NilT) NilT NilT) (Tri 5 NilT NilT NilT)
```

a) Dar el tipo y definir la función `foldAT` que implementa el esquema de recursión estructural para el tipo `AT a`. Sólo en este inciso se permite usar recursión explícita.

b) Definir la función `preorder :: AT a -> [a]`, que lista los nodos de un árbol ternario en el orden en que aparecen: primero la raíz, después los nodos del subárbol izquierdo, luego los del medio y finalmente los del derecho.
Por ejemplo: `preorder at1 ~> [1, 2, 3, 4, 5]`.

c) Definir la función `mapAT :: (a -> b) -> AT a -> AT b`, análoga a la función `map` para listas, pero para árboles ternarios.
Por ejemplo: `mapAT (+1) at1 ~> Tri 2 (Tri 3 NilT NilT NilT) (Tri 4 (Tri 5 NilT NilT) NilT NilT) (Tri 6 NilT NilT NilT)`.

d) Definir la función `nivel :: AT a -> Int -> [a]`, que devuelve la lista de nodos del nivel correspondiente del árbol, siendo 0 el nivel de la raíz.
Por ejemplo: `nivel at1 1 ~> [2, 3, 5]`.
Pista: aprovechar la currificación y utilizar evaluación parcial.

### Resolución
```haskell
-- a) foldAT
foldAT :: b -> (a -> b -> b -> b -> b) -> AT a -> b
foldAT cNil cTri t = case t of
    NilT -> cNil
    Tri x i m d -> cTri x (rec i) (rec m) (rec d)
        where rec = foldAT cNil cTri

-- b) preorder
preorder :: AT a -> [a]
preorder = foldAT [] (\x ri rm rd -> x : (ri ++ rm ++ rd))

-- c) mapAT
mapAT :: (a -> b) -> AT a -> AT b
mapAT f = foldAT (NilT) (\x ri rm rd -> Tri (f x) ri rm rd)

-- d) nivel
nivel :: AT a -> Int -> [a]
nivel = foldAT (\i -> []) (\x ri rm rd -> \i ->
    if i == 0
    then [x]
    else ((ri (i-1)) ++ (rm (i-1)) ++ (rd (i-1))))
```

### Explicación y Análisis
- **Inciso a:** Se implementa el esquema de recursión estructural `foldAT`. El caso base recibe una constante `cNil` para `NilT`, y el caso recursivo procesa un nodo `Tri` usando la función `cTri`, pasando el valor de la raíz `x` y el resultado de la recursión sobre los tres subárboles (izquierdo, medio y derecho).
- **Inciso b:** El recorrido preorder se implementa en términos de `foldAT`. Para el caso base se devuelve la lista vacía `[]`. En el paso recursivo se concatena el valor actual `x` con el resultado recursivo de los subárboles en el orden correcto (izquierdo `ri`, medio `rm`, derecho `rd`).
- **Inciso c:** La función `mapAT` sigue el esquema clásico. Para reconstruir el árbol se utiliza el constructor `Tri`, aplicando la función `f` al elemento de la raíz y manteniendo los subárboles resultantes `ri`, `rm` y `rd`.
- **Inciso d:** Para `nivel`, se aprovecha la currificación haciendo que el `foldAT` devuelva una función de tipo `Int -> [a]`. El caso base (árbol nulo) ignora el nivel pedido y devuelve `[]`. El caso inductivo examina el nivel `i`: si es `0`, devuelve sólo la raíz del subárbol actual en una lista `[x]`; si no lo es, avanza un nivel consultando el nivel `i-1` de forma recursiva en los tres subárboles y concatena los resultados.

### Chuleta
- **fold:** Su tipo debe tener tantos argumentos como constructores tenga el tipo de dato. Las funciones del caso recursivo reciben los parámetros originales de ese constructor (excepto los que son del tipo recursivo, que son reemplazados por el resultado de la recursión).
- **Currificación en fold:** Si se necesita acumular información externa en el `fold` (como la profundidad), hacer que el `fold` construya y devuelva una función de tipo `Info -> Resultado` y luego aplicar el `Info` externamente.

## Ejercicio 2 - Demostración de propiedades

### Enunciado
Considerar las siguientes definiciones:
```haskell
data AEB a = Hoja a | Bin (AEB a) a (AEB a)

const :: a -> b -> a
{C} const = (\x -> \y -> x)

head :: [a] -> a
{H} head (x:xs) = x

tail :: [a] -> [a]
{T} tail (x:xs) = xs

length :: [a] -> Int
{L0} length [] = 0
{L1} length (x:xs) = 1 + length xs

null :: [a] -> Bool
{N0} null [] = True
{N1} null (x:xs) = False

altura :: AEB a -> Int
{A0} altura (Hoja x) = 1
{A1} altura (Bin i r d) = 1 + max (altura i) (altura d)

esPreRama :: Eq a => AEB a -> [a] -> Bool
{E0} esPreRama (Hoja x) = \xs -> null xs || (xs == [x])
{E1} esPreRama (Bin i r d) = \xs -> null xs || (r == head xs && (esPreRama i (tail xs) || esPreRama d (tail xs)))
```

a) Asumiendo `Eq a`, demostrar la siguiente propiedad:
`forall t::AEB a . forall xs::[a] . esPreRama t xs => length xs <= altura t`

b) Demostrar el siguiente teorema usando deducción natural, sin utilizar principios clásicos:
`((P => Q) ^ (Q => R)) => ¬R => ¬P`

### Resolución

**Parte a) Demostración de propiedad (incompleta en original)**
Por inducción en la estructura del árbol binario estricto (AEB).
Sea `P(t) = forall xs::[a] . esPreRama t xs -> length xs <= altura t`

**Caso Base:** `t = Hoja h`
Debemos probar: `forall xs::[a] . esPreRama (Hoja h) xs -> length xs <= altura (Hoja h)`
Desenrollamos `{E0}` y `{A0}`:
`forall xs::[a] . null xs || (xs == [h]) -> length xs <= 1`
Se puede demostrar por casos analizando el valor de `xs`:
- Si `xs = []`: `null [] || ([] == [h]) -> True || False -> True`. El lado derecho es `length [] <= 1 -> 0 <= 1 -> True`. `True -> True`.
- Si `xs = y:ys`: se prueba que, para que el antecedente sea válido, `ys` debe ser vacío (por la igualdad con `[h]`), lo cual hace que `length [y] <= 1 -> 1 <= 1`, siendo verdadero.

**Paso Inductivo:** `t = Bin i r d`
HI 1: `forall xs::[a] . esPreRama i xs -> length xs <= altura i`
HI 2: `forall xs::[a] . esPreRama d xs -> length xs <= altura d`
Tesis: `forall xs::[a] . esPreRama (Bin i r d) xs -> length xs <= altura (Bin i r d)`

Reemplazando por {E1} y {A1}:
`forall xs::[a] . null xs || (r == head xs && (esPreRama i (tail xs) || esPreRama d (tail xs))) -> length xs <= 1 + max (altura i) (altura d)`
Caso `xs = []`: el lado izquierdo da `True` por `null []`, y la longitud es 0. `0 <= 1 + max(...)` es verdadero.
Caso `xs = y:ys`: `null (y:ys)` es Falso. El antecedente queda:
`(r == head (y:ys) && (esPreRama i ys || esPreRama d ys))`
Si asumimos el antecedente verdadero, tenemos que `esPreRama i ys || esPreRama d ys` es verdadero. Por las hipótesis inductivas, esto implica que `length ys <= altura i` o `length ys <= altura d`. En cualquier caso, `length ys <= max (altura i) (altura d)`.
Por definición, `length (y:ys) = 1 + length ys`. Entonces:
`1 + length ys <= 1 + max (altura i) (altura d)` que es lo que queríamos demostrar.

**Parte b) Deducción Natural (incompleta en original)**
```text
  [P]1     [(P => Q) ^ (Q => R)]3
  ------------------------------- ^e1
           P => Q                                     [(P => Q) ^ (Q => R)]3
  ----------------------------------- ->e             ---------------------- ^e2
               Q                                              Q => R
  ------------------------------------------------------------------ ->e
                                 R                                          [¬R]2
  ------------------------------------------------------------------------------- MT / ->e
                                    False
--------------------------------------------- ->i (1)
                                     ¬P
--------------------------------------------- ->i (2)
                                 ¬R => ¬P
--------------------------------------------- ->i (3)
              ((P => Q) ^ (Q => R)) => ¬R => ¬P
```

### Explicación y Análisis
- **Inciso a:** El estudiante intentó probar el caso base usando inducción en listas y extensionalidad de booleanos, que es un enfoque posible pero excesivamente complejo; la corrección indicó "No hacía falta, se podía usar extensionalidad de forma más directa" separando por casos. En el paso inductivo el estudiante tuvo la idea correcta pero se frenó en la extensionalidad de booleanos sin llegar a utilizar las Hipótesis Inductivas de manera clara. Se muestra aquí la resolución completa basándose en su estructura.
- **Inciso b:** El estudiante no logró derivar el árbol completo. Se debe desarmar la conjunción del antecedente principal en sus implicaciones y concatenarlas (transitividad de implicación) para llegar a R, que contradice a ¬R introducido por la hipótesis a descargar, permitiendo derivar ¬P introduciendo así la negación correspondiente a P.

### Chuleta
- **Inducción en Árboles:** Siempre separar `Caso Base` (Hojas) y `Paso Inductivo` (Nodos intermedios, para los cuales se asume la HI sobre los hijos).
- **Implicaciones lógicas en inducción:** El formato típico del objetivo es `Antecedente -> Consecuente`. Se asume verdadero el antecedente para demostrar el consecuente, de lo contrario la implicación ya es lógicamente válida.

## Ejercicio 3 - Cálculo Lambda Tipado

### Enunciado
Se desea extender el cálculo lambda simplemente tipado para modelar Diccionarios.
`tau ::= ... | Dicc(sigma, tau)`
`M ::= ... | Vacio_{sigma,tau} | definir(M, M, M) | def?(M, M) | obtener(M, M)`

a. Introducir las reglas de tipado.
b. Definir el conjunto de valores y reglas de semántica operacional.
c. Mostrar la reducción de una expresión.

### Resolución

**a) Reglas de Tipado**
```text
--------------------------------- ax_vacio
Gamma |- Vacio_{sigma,tau} : Dicc(sigma, tau)

Gamma |- M : Dicc(sigma, tau)    Gamma |- N : sigma    Gamma |- O : tau
------------------------------------------------------------------ definir
Gamma |- definir(M, N, O) : Dicc(sigma, tau)

Gamma |- M : Dicc(sigma, tau)    Gamma |- N : sigma
--------------------------------------------------- def?
Gamma |- def?(M, N) : Bool

Gamma |- M : Dicc(sigma, tau)    Gamma |- N : sigma
--------------------------------------------------- obtener
Gamma |- obtener(M, N) : tau
```

**b) Semántica Operacional**
Valores:
`V ::= ... | Vacio_{sigma,tau} | definir(V, V, V)`

Reglas:
```text
(def?V)   def?(Vacio_{sigma,tau}, W) -> False
(def?X)   def?(definir(V, W, U), W') -> if W == W' then True else def?(V, W')
(obtX)    obtener(definir(V, W, U), W') -> if W == W' then U else obtener(V, W')
(obtV)    obtener(Vacio_{sigma,tau}, W) -> obtener(Vacio_{sigma,tau}, W)  // Se cuelga (termina sin ser un valor)
```
Hay 7 reglas de congruencia implícitas: 3 para `definir`, 2 para `def?` y 2 para `obtener`.

**c) Reducción**
Expresión:
`(lambda d: Dicc(Nat, Bool). if def?(d, 0) then obtener(d, 0) else False) definir(Vacio_{Nat,Bool}, 0, True)`

1. **(beta)** (sustitución en el if):
`if def?(definir(Vacio_{Nat,Bool}, 0, True), 0) then obtener(definir(Vacio_{Nat,Bool}, 0, True), 0) else False`

2. **(if_c + def?X)** (evaluar la condición usando def?X):
`if (if 0 == 0 then True else def?(Vacio_{Nat,Bool}, 0)) then obtener(definir(Vacio_{Nat,Bool}, 0, True), 0) else False`

3. **(if_c + if_t + 0==0 + if_t)** (evaluar igualdades e if interior. Nota: el estudiante saltó algunos de estos pasos intermedios):
`if True then obtener(definir(Vacio_{Nat,Bool}, 0, True), 0) else False`

4. **(if_t)** (resolver el if exterior evaluado a True):
`obtener(definir(Vacio_{Nat,Bool}, 0, True), 0)`

5. **(obtX)**:
`if 0 == 0 then True else obtener(Vacio_{Nat,Bool}, 0)`

6. **(0==0 + if_t)**:
`True`

### Explicación y Análisis
- **Tipado:** Las reglas son directas e implican que las operaciones conserven los tipos `sigma` (clave) y `tau` (valor).
- **Semántica:** Los diccionarios se modelan estructuralmente como listas de pares encadenados por llamadas a `definir`. Es por eso que se extienden los Valores para permitir diccionarios parcial o totalmente definidos.
- **Reducción:** Un error común del estudiante es combinar demasiados pasos de congruencia que deben resolverse estrictamente paso a paso (por ejemplo, el paso de `0==0` requiere una congruencia del `if` sobre la condición antes de evaluar el condicional mismo). El corrector le señaló `SALTEA PASOS`.

### Chuleta
- **Valores en extensiones (Listas, Diccionarios, Árboles):** Típicamente los constructores como `Vacio`, `Cons` o `definir` se consideran constructores de Valores cuando sus argumentos ya han sido reducidos a Valores (por ej. `definir(V1, V2, V3)` es un valor).
- **Reducción paso a paso:** Ser escrupuloso con las reglas de congruencia. No se puede evaluar el cuerpo de un `if` o el resultado de un `==` simultáneamente con el avance de la semántica de la expresión contenedora.
