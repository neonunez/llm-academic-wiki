## Ejercicio 1 - Programación Funcional

### Enunciado
Se define un sistema de archivos `FS` que no admite enlaces. 
```haskell
data FS = Arch String | Dir String [FS] deriving (Eq, Show)
```
a) Dar el tipo y definir `foldFS` y `recFS`.
b) Definir la función `rutas :: FS -> [String]`, listando los caminos internos separados por `/`.
c) Definir `valido :: FS -> Bool`, verificando que los nombres dentro de un mismo directorio sean únicos. Sugiere usar `all` y `nub`.
d) Definir `rutasPosibles :: [String] -> [String]` usando listas por comprensión que genera rutas infinitas con una profundidad autoincremental usando la secuencia infinita `[0..]`.

### Resolución
```haskell
-- a)
foldFS :: (String -> sol) -> (String -> [sol] -> sol) -> FS -> sol
foldFS fArch fDir fs = case fs of
  (Arch s) -> fArch s
  (Dir s subfss) -> fDir s (map (foldFS fArch fDir) subfss)

recFS :: (String -> sol) -> (String -> [FS] -> [sol] -> sol) -> FS -> sol
recFS fArch fDir fs = case fs of
  (Arch s) -> fArch s
  (Dir s subfss) -> fDir s subfss (map (recFS fArch fDir) subfss)

-- b)
rutas :: FS -> [String]
rutas = foldFS (\s -> [s]) 
               (\s subs -> s : (map (\ruta -> s ++ "/" ++ ruta) (concat subs)))

-- c)
valido :: FS -> Bool
valido = recFS (const True)
  (\s subfss subsols -> (all id subsols) && 
    length (map nombre subfss) == length (nub (map nombre subfss)))

nombre :: FS -> String
nombre fs = case fs of
  (Arch s) -> s
  (Dir s _) -> s

-- d)
rutasPosibles xss = concatMap nombresConNBarras [0..]
  where nombresConNBarras = foldNat (\rs -> [s1 ++ "/" ++ s2 | s1 <- rs, s2 <- xss]) xss
```

### Explicación y Análisis
- **El tipo FS:** Es un árbol n-ario o rose-tree. Esto requiere recursión mutua implícita mapeando el esquema estructural en la lista de los subdirectorios.
- **`rutas`:** El resultado en cada rama es una lista de Strings (`[String]`). Por ende, `subs` tiene tipo `[[String]]`. Hay que hacer un `concat` primero para aplanar las rutas que vienen de abajo, y luego mapear prependiendo `s ++ "/"`.
- **`valido`:** Se utiliza `recFS` porque la unicidad se comprueba usando la información intacta de la estructura subyacente (los `subfss`) y llamando a la función auxiliar `nombre`. La comprobación de unicidad `length subfss == length (nub subfss)` es un patrón muy común para conjuntos pequeños.
- **`rutasPosibles`:** Usar `foldNat` con iterador sobre la base `[0..]` permite generar el conjunto infinito iterativo en capas (nombres con 0 barras, luego 1 barra, etc.) de forma no estricta (lazy).

## Ejercicio 2 - Demostración de Propiedades y Deducción Natural

### Enunciado a)
Demostrar por inducción en el `Arbol123`: `forall c::a . forall n::Int . tamaño (truncar c t n) <= tamaño t`
(Dado que es de aridad variable `Hoja`, `Dos` y `Tres`).

### Resolución a)
Inducción en la estructura. Se abren los casos para cada constructor.
Dado que la función `truncar` se implementa devolviendo una lambda `\n -> ...`, al instanciarla en el lado izquierdo hay que aplicarle el `n`.
En el paso inductivo, tras instanciar el `if n<1 then ... else ...`, la prueba abre los dos casos booleanos. El caso base de profundidad cae al caso `tamaño (Hoja c) = 1` y acota por el Lema que el árbol original tiene un tamaño de 1 o más. El caso recursivo es directo usando HI y desigualdad aditiva monótona de enteros.

### Enunciado b)
Demostrar por deducción natural: `((pi => rho) v (sigma => tau)) => (sigma ^ pi) => (rho v tau)`

### Resolución b)
La técnica subyacente es: al estar el condicional del lado derecho precedido por una conjunción (`sigma ^ pi`), es imperativo asumir esa conjunción e inmediatamente derivar ambas componentes individuales con reglas de eliminación `^e1` y `^e2` para tener `sigma` y `pi` disponibles individualmente en el entorno.
Luego se usa la disyunción primaria en un `vE` (eliminación de la disyunción). En ambas ramas el antecedente necesario estará disponible (uno será `pi` que activa a `rho`, y el otro `sigma` que activa a `tau`).

## Ejercicio 3 - Cálculo Lambda Tipado

### Enunciado
Extender el cálculo lambda tipado para "anillos" (`M :: M` o `(M)`). `actual` lee la punta, y `avanzar` lo rota en una posición.

### Resolución
El alumno define una estructura lineal con una sintaxis curiosa. Un anillo se construye con `(V)` y se agregan elementos pegándolos a la derecha con `::` (ej. `(A) :: B :: C`).
El problema del alumno y la corrección posterior giran en torno a **cómo rotar la estructura de datos**.

**Problema Semántico (Regla de rotación de Anillos):**
Para implementar `avanzar`, el último elemento introducido en el historial (el más a la derecha en la sintaxis, o sea el más superficial en el AST `(A) :: B`) debe pasar a envolver al resto, y la estructura interna debe correrse. El alumno intentó hacer pattern matching semántico tipo `avanzar( ((V) :: W) :: U ) -> (U) :: sinLlaves(V) :: W` inventando macros ajenas al lenguaje formal del cálculo lambda tipado estándar (como funciones en el metalenguaje `sinLlaves` no definidas semánticamente).

La falla pedagógica aquí (y por lo que el alumno es corregido) es la ausencia de constructos primitivos bien tipados para manejar estado en anillos sin un constructor envolvente que delimite claramente el inicio/fin del búfer rotacional para su reestructuración recursiva formal, demostrando lo complejo que es implementar estructuras circulares semánticamente puras.
