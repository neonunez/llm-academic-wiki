## Ejercicio 1 - Programación Funcional

### Enunciado
Aclaración: en este ejercicio no está permitido utilizar recursión explícita, a menos que se indique lo contrario.
En este ejercicio vamos a modelar lógica proposicional en Haskell, de modo de poder construir fórmulas proposicionales y evaluarlas bajo distintas valuaciones.

```haskell
data Prop = Var String | No Prop | Y Prop Prop | O Prop Prop | Imp Prop Prop
type Valuación = String -> Bool
```

a) Dar el tipo y definir las funciones `foldProp` y `recProp`, que implementan respectivamente los esquemas de recursión estructural y primitiva para el tipo `Prop`. Solo en este inciso se permite usar recursión explícita.
b) Definir la función `variables :: Prop -> [String]`, que dada una fórmula devuelve la lista con todas sus variables proposicionales en algún orden, sin elementos repetidos.
c) Definir la función `evaluar :: Valuación -> Prop -> Bool`, que indica si una fórmula es verdadera o falsa para una valuación dada.
d) Definir la función `estáEnFNN :: Prop -> Bool`, que indica si una fórmula está en Forma Normal Negada. Es decir, si no tiene implicaciones y la negación se aplica únicamente a variables y no a proposiciones más complejas.

### Resolución
```haskell
-- a) foldProp y recProp
foldProp :: (String -> a) -> (a -> a) -> (a -> a -> a) -> (a -> a -> a) -> (a -> a -> a) -> Prop -> a
foldProp fvar _ _ _ _ (Var s) = fvar s
foldProp fvar fnot fy fo fimp (No p) = fnot (foldProp fvar fnot fy fo fimp p)
foldProp fvar fnot fy fo fimp (Y p1 p2) = fy (foldProp fvar fnot fy fo fimp p1) (foldProp fvar fnot fy fo fimp p2)
foldProp fvar fnot fy fo fimp (O p1 p2) = fo (foldProp fvar fnot fy fo fimp p1) (foldProp fvar fnot fy fo fimp p2)
foldProp fvar fnot fy fo fimp (Imp p1 p2) = fimp (foldProp fvar fnot fy fo fimp p1) (foldProp fvar fnot fy fo fimp p2)

recProp :: (String -> a) -> (Prop -> a -> a) -> (Prop -> Prop -> a -> a -> a) -> (Prop -> Prop -> a -> a -> a) -> (Prop -> Prop -> a -> a -> a) -> Prop -> a
recProp fvar _ _ _ _ (Var s) = fvar s
recProp fvar fnot fy fo fimp (No p) = fnot p (recProp fvar fnot fy fo fimp p)
recProp fvar fnot fy fo fimp (Y p1 p2) = fy p1 p2 (recProp fvar fnot fy fo fimp p1) (recProp fvar fnot fy fo fimp p2)
recProp fvar fnot fy fo fimp (O p1 p2) = fo p1 p2 (recProp fvar fnot fy fo fimp p1) (recProp fvar fnot fy fo fimp p2)
recProp fvar fnot fy fo fimp (Imp p1 p2) = fimp p1 p2 (recProp fvar fnot fy fo fimp p1) (recProp fvar fnot fy fo fimp p2)

-- b) variables
variables :: Prop -> [String]
variables p = eliminarRepetidos (foldProp (\s -> [s]) id (++) (++) (++) p)
  where
    eliminarRepetidos = foldr (\x r -> if elem x r then r else x:r) []

-- c) evaluar
evaluar :: Valuación -> Prop -> Bool
evaluar val = foldProp val not (&&) (||) (\r1 r2 -> not r1 || r2)

-- d) estáEnFNN
estáEnFNN :: Prop -> Bool
estáEnFNN = recProp (const True) faux (\_ _ r1 r2 -> r1 && r2) (\_ _ r1 r2 -> r1 && r2) (\_ _ _ _ -> False)
  where
    faux (Var _) _ = True
    faux _ _ = False
```

### Explicación y Análisis
- **foldProp/recProp:** La estructura tiene 5 constructores, por lo tanto el esquema requiere 5 funciones como argumentos extra, uno por cada constructor.
- **variables:** El corrector señaló que se podría haber usado `union` en vez de `++` y una función auxiliar para evitar repetidos, ya que `union` de `Data.List` garantiza la no repetición de elementos si se usa consistentemente. Aquí la solución implementada con `foldr` logra el mismo efecto.
- **evaluar:** Sustitución directa de constructores por operadores booleanos lógicos equivalentes, recordando que `A => B` equivale a `¬A || B`.
- **estáEnFNN:** Se requiere usar `recProp` porque el comportamiento recursivo depende de si el nodo hijo en un constructor `No` es específicamente una variable (lo cual es accesible inspeccionando la estructura preservada por la recursión primitiva).

### Chuleta
- **recProp vs foldProp:** `rec` es necesario cuando el resultado en el nivel actual depende no solo del resultado de evaluar los subárboles, sino también de la forma original de dichos subárboles (como mirar si el subárbol es `Var x`).

## Ejercicio 2 - Demostración e inferencia

### Enunciado
Dada las definiciones:
```haskell
data AIH a = Hoja a | Bin (AIH a) (AIH a)

esHoja :: AIH a -> Bool
{E0} esHoja (Hoja x) = True
{E1} esHoja (Bin i d) = False

der :: AIH a -> AIH a
{D} der (Bin i d) = d

izq :: AIH a -> AIH a
{I} izq (Bin i d) = i

mismaEstructura :: AIH a -> AIH a -> Bool
{M0} mismaEstructura (Hoja x) = esHoja
{M1} mismaEstructura (Bin i d) = \t -> not (esHoja t) && mismaEstructura i (izq t) && mismaEstructura d (der t)
```

a) Demostrar: `forall t::AIH a . forall u::AIH a . mismaEstructura t u = mismaEstructura u t`
b) Usar Algoritmo W para inferir tipado de:
i) `(\x.x(\x.Succ(x)))(\x.x)`
ii) `\x.if isZero(x) then x else x zero`

### Resolución

**a) Demostración de Propiedades**
Por inducción en `t`.
P(t) = `forall u::AIH a . mismaEstructura t u = mismaEstructura u t`

**Caso Base:** `t = Hoja n`.
P(Hoja n): `forall u . mismaEstructura (Hoja n) u = mismaEstructura u (Hoja n)`
Por extensionalidad en `u`:
- **Subcaso `u = Hoja m`:**
  `mismaEstructura (Hoja n) (Hoja m)` -> por {M0} -> `esHoja (Hoja m)` -> por {E0} -> `True`.
  `mismaEstructura (Hoja m) (Hoja n)` -> por {M0} -> `esHoja (Hoja n)` -> por {E0} -> `True`.
  Queda demostrado `True = True`.
- **Subcaso `u = Bin l r`:**
  `mismaEstructura (Hoja n) (Bin l r)` -> por {M0} -> `esHoja (Bin l r)` -> por {E1} -> `False`.
  `mismaEstructura (Bin l r) (Hoja n)` -> por {M1} -> `not (esHoja (Hoja n)) && ...` -> `not True && ...` -> `False && ...` -> `False`.
  Queda demostrado `False = False`.

**Paso Inductivo:** `t = Bin i d`.
HI: `P(i) ^ P(d)`.
Por extensionalidad en `u`:
- **Subcaso `u = Hoja m`:**
  `mismaEstructura (Bin i d) (Hoja m)` -> por {M1} -> `not (esHoja (Hoja m)) && ...` -> `not True && ...` -> `False`.
  `mismaEstructura (Hoja m) (Bin i d)` -> por {M0} -> `esHoja (Bin i d)` -> `False`.
  Queda demostrado `False = False`.
- **Subcaso `u = Bin l r`:**
  Lado Izquierdo: `mismaEstructura (Bin i d) (Bin l r)`
  -> por {M1} -> `not (esHoja (Bin l r)) && mismaEstructura i (izq (Bin l r)) && mismaEstructura d (der (Bin l r))`
  -> por {E1}, {I}, {D} -> `not False && mismaEstructura i l && mismaEstructura d r`
  -> `True && mismaEstructura i l && mismaEstructura d r`
  -> `mismaEstructura i l && mismaEstructura d r`.

  Lado Derecho: `mismaEstructura (Bin l r) (Bin i d)`
  -> por análogo {M1, E1, I, D} -> `mismaEstructura l i && mismaEstructura r d`.

  Por HI en i y en d: `mismaEstructura i l = mismaEstructura l i`, y `mismaEstructura d r = mismaEstructura r d`.
  Por lo tanto, ambas expresiones son idénticas.

**b) Algoritmo W**
i) `(\x.x(\x.Succ(x)))(\x.x)`
1. `W(\x.x) -> vacio |- \x:X9 . x : X9 -> X9`
2. `W(\x.Succ(x)) -> vacio |- \x:Nat.Succ(x) : Nat -> Nat`
3. `W(x(\x.Succ(x))) -> x:((Nat->Nat)->X5) |- x(\x.Succ(x)) : X5`
4. `W(\x.x(\x.Succ(x))) -> vacio |- \x:((Nat->Nat)->X5) . x(\x.Succ(x)) : ((Nat->Nat)->X5) -> X5`
5. Al hacer Aplicación de `4` a `1`, se debe unificar el tipo del dominio de la primera función con el tipo de la segunda:
   `((Nat->Nat)->X5) =? (X9->X9)`
   Resolviendo MGU: `X9 := Nat->Nat`, lo que forzaría a que el lado derecho sea `(Nat->Nat)->(Nat->Nat)`.
   Igualando con el lado izquierdo `(Nat->Nat)->X5`, esto implica `X5 := Nat->Nat`.
   **(Nota de corrección):** El alumno inicialmente se equivocó con los paréntesis, llevando a un Occur Check (`X5 = X5 -> X5`), pero la tipificación correcta sí es válida y el tipo inferido es `(Nat->Nat) -> (Nat->Nat)`.

ii) `\x.if isZero(x) then x else x zero`
Para `if isZero(x) then x else x zero`:
1. `x` en `isZero(x)` fuerza que `x: Nat`.
2. `x zero` implica que `x` es una función aplicable a algo de tipo `Nat` (`zero: Nat`), es decir `x: Nat -> X6`.
Al unificar los requerimientos de `x` (`Nat =? Nat -> X6`), ocurre un Clash o Falla por Occur Check.
Por lo tanto, la expresión no tipa.

### Explicación y Análisis
- **Extensionalidad cruzada:** En el inciso a), se pide inducción en la estructura del primer parámetro pero el segundo parámetro requiere análisis por casos (extensionalidad). Es imperativo separar claramente los niveles.
- **Tipado e Inferencias:** El algoritmo W es muy estricto con los paréntesis en las unificaciones. Un error común es mezclar asociatividades. Las flechas asocian a derecha (`A -> B -> C` es `A -> (B -> C)`), lo cual hay que respetar en las sustituciones.

## Ejercicio 3 - Cálculo Lambda Tipado

### Enunciado
Extensión de árboles AIH:
```text
tau ::= ... | AIH(tau)
M ::= ... | Hoja(M) | Bin(M, M) | case M of Hoja x ~> M1 ; Bin(i, d) ~> M2
```
a) Reglas de Tipado
b) Reglas de Semántica Operacional
c) Mostrar reducción de: `case (\n:Nat. Hoja(n)) Succ(zero) of Hoja x ~> Succ(Pred(x)) ; Bin(i, d) ~> zero`

### Resolución

**a) Reglas de Tipado**
```text
Gamma |- M : tau
-------------------------- hojaM
Gamma |- Hoja(M) : AIH(tau)

Gamma |- M1 : AIH(tau)     Gamma |- M2 : AIH(tau)
----------------------------------------------------- Bin
Gamma |- Bin(M1, M2) : AIH(tau)

Gamma |- M : AIH(tau)   Gamma, x:tau |- M1 : sigma   Gamma, i:AIH(tau), d:AIH(tau) |- M2 : sigma
------------------------------------------------------------------------------------------------ case
Gamma |- case M of Hoja x ~> M1 ; Bin(i, d) ~> M2 : sigma
```

**b) Semántica Operacional**
Valores:
`V ::= ... | Hoja(V) | Bin(V, V)`

Reglas de Cómputo:
```text
case Hoja(V) of Hoja x ~> M1 ; Bin(i, d) ~> M2  -->  M1{x:=V}

case Bin(V1, V2) of Hoja x ~> M1 ; Bin(i, d) ~> M2  -->  M2{i:=V1, d:=V2}
```

Reglas de Congruencia:
- Si `M --> M'`, entonces `Hoja(M) --> Hoja(M')`
- Si `M1 --> M1'`, entonces `Bin(M1, M2) --> Bin(M1', M2)`
- Si `M2 --> M2'`, entonces `Bin(V, M2) --> Bin(V, M2')`
- Si `M --> M'`, entonces `case M of ... --> case M' of ...`

**c) Reducción**
Expresión: `case (\n:Nat. Hoja(n)) Succ(zero) of Hoja x ~> Succ(Pred(x)) ; Bin(i, d) ~> zero`

1. Por congruencia del `case` evaluamos el discriminante (que es una aplicación). Por Beta:
`(\n:Nat. Hoja(n)) Succ(zero) --> Hoja(Succ(zero))`
La expresión completa queda:
`case Hoja(Succ(zero)) of Hoja x ~> Succ(Pred(x)) ; Bin(i, d) ~> zero`

2. Por regla de cómputo del case de la hoja:
`Succ(Pred(x)){x:=Succ(zero)}`
-> `Succ(Pred(Succ(zero)))`

3. Por regla de cómputo de `Pred` (asumida del estándar):
`Pred(Succ(zero)) --> zero`
-> `Succ(zero)`

### Explicación y Análisis
- **Tipado del Case:** El `case` introduce variables ligadas (`x` en la rama hoja, `i` y `d` en la rama bin). Sus tipos se infieren de la estructura observada (`tau` para el contenido de la hoja, y la estructura recursiva `AIH(tau)` para los subárboles).
- **Valores Inductivos:** Como la estructura de datos envuelve otras expresiones, un árbol sólo es un valor final si todos sus componentes internos también lo son.
- **Reducción:** Se aplica orden normal o aplicativo (según el cálculo), aquí el evaluador usa congruencia para avanzar el discriminante del case y luego efectúa la sustitución principal.
