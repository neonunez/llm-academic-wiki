## Ejercicio 1 - Programación Funcional

### Enunciado
Se define el tipo de datos `ABNV a`, que representa árboles binarios no vacíos con elementos de tipo `a`:
```haskell
data ABNV a = Hoja a | Uni a (ABNV a) | Bi (ABNV a) a (ABNV a)
```

a) Definir `foldABNV` y `recABNV` para el tipo `ABNV a`.
b) Definir `elemABNV :: Eq a => a -> ABNV a -> Bool`, que indica si un elemento pertenece al árbol.
c) Definir `reemplazarUno :: Eq a => a -> a -> ABNV a -> ABNV a` que reemplaza la primera aparición de `x` por `y` (en orden preorder).
d) Definir `nivel :: ABNV a -> Int -> [a]`, que liste todos los elementos del nivel indicado, siendo 0 la raíz. Resolver con currificación y evaluación parcial.

### Resolución
```haskell
-- a)
foldABNV :: (a -> b) -> (a -> b -> b) -> (b -> a -> b -> b) -> ABNV a -> b
foldABNV fHoja fUni fBi (Hoja v) = fHoja v
foldABNV fHoja fUni fBi (Uni v ar) = fUni v (foldABNV fHoja fUni fBi ar)
foldABNV fHoja fUni fBi (Bi i v d) = fBi (foldABNV fHoja fUni fBi i) v (foldABNV fHoja fUni fBi d)

recABNV :: (a -> b) -> (a -> ABNV a -> b -> b) -> (ABNV a -> b -> a -> ABNV a -> b -> b) -> ABNV a -> b
recABNV fHoja fUni fBi (Hoja v) = fHoja v
recABNV fHoja fUni fBi (Uni v ar) = fUni v ar (recABNV fHoja fUni fBi ar)
recABNV fHoja fUni fBi (Bi i v d) = fBi i (recABNV fHoja fUni fBi i) v d (recABNV fHoja fUni fBi d)

-- b)
elemABNV :: Eq a => a -> ABNV a -> Bool
elemABNV e = foldABNV (\v -> v == e) (\v rec -> (v == e) || rec) (\reci v recd -> (v == e) || reci || recd)

-- c)
reemplazarUno :: Eq a => a -> a -> ABNV a -> ABNV a
reemplazarUno x y = recABNV 
  (\v -> if x == v then Hoja y else Hoja v)
  (\v ar rec -> if x == v then Uni y ar else Uni v rec)
  (\i reci v d recd -> 
      if x == v then Bi i y d 
      else if elemABNV x i then Bi reci v d 
      else Bi i v recd)

-- d)
nivel :: ABNV a -> Int -> [a]
nivel = foldABNV
  (\v -> (\n -> if n == 0 then [v] else []))
  (\v rec -> (\n -> if n == 0 then [v] else rec (n-1)))
  (\reci v recd -> (\n -> if n == 0 then [v] else reci (n-1) ++ recd (n-1)))
```

### Explicación y Análisis
- **Estructura ABNV:** A diferencia del árbol binario clásico, este no tiene un constructor vacío. El caso base es `Hoja a`.
- **`reemplazarUno`:** Requiere recursión primitiva porque al encontrar el elemento a reemplazar, el resto del árbol original debe mantenerse intacto (no seguir iterando ni transformando). Además, en el constructor `Bi`, el orden "preorder" exige primero chequear la raíz (`v`), si no está ahí, buscar en el subárbol izquierdo (`i`) usando una función como `elemABNV` para decidir a qué lado mandar la recursión, y si no está en el izquierdo, mandarla al derecho.
- **`nivel`:** El enunciado pide usar evaluación parcial. Al devolver una función `\n -> ...` desde el fold, aprovechamos el esquema para procesar el árbol de una sola vez devolviendo una función que espera la profundidad `n`.

### Chuleta
- **Preorder en reemplazos:** "Primero raíz, luego izquierda, luego derecha". En recursiones esquemáticas esto obliga a chequear ramas enteras con observadores (ej. `elemABNV`) antes de usar el resultado de las llamadas recursivas, para asegurar que se reemplaza solo la *primera* aparición.

## Ejercicio 2 - Demostración de propiedades y Deducción Natural

### Enunciado a)
Sea el árbol tradicional `AB a`.
```haskell
elemAB x (Bin i r d) = (x == r) || (elemAB x i) || (elemAB x d)
mapAB f (Bin i r d) = Bin (mapAB f i) (f r) (mapAB f d)
```
Demostrar: `forall t::AB a . forall x::a . forall f::a -> b . (elemAB x t => elemAB (f x) (mapAB f t))`

### Resolución a)
Inducción estructural en `t`.
P(t) = `forall x::a. forall f::a->b . (elemAB x t => elemAB (f x) (mapAB f t))`

**Caso Base `P(Nil)`:**
`elemAB x Nil => elemAB (f x) (mapAB f Nil)`
`False => ...` que es `True` por lógica (implicación material).

**Paso Inductivo `P(Bin i r d)`:**
HI: `P(i)` y `P(d)`.
`elemAB x (Bin i r d) => elemAB (f x) (mapAB f (Bin i r d))`
Asumo que el antecedente es `True` (si es `False`, trivialmente vale).
`elemAB x (Bin i r d) = (x == r) || elemAB x i || elemAB x d = True`.
Por lema de generación de booleanos (Or), divido en tres casos:
1. `x == r = True`: Por congruencia de igualdad, `f x == f r`.
   El lado derecho evaluará a `(f x == f r) || ...` lo que será `True || ... = True`. Vale.
2. `elemAB x i = True`: Por HI en `i`, `elemAB (f x) (mapAB f i) = True`.
   El lado derecho evaluará a `... || elemAB (f x) (mapAB f i) || ...` que es `True`. Vale.
3. `elemAB x d = True`: Por HI en `d`, similar al caso 2.
Demostrado.

### Enunciado b)
Demostrar por deducción natural: `p => (sigma v (p => tau)) => (sigma v tau)`

### Resolución b)
```text
      [p] (1)   [p => tau] (3)
      ------------------------ =>E
               tau
      ------------------ vI2
         sigma v tau
-----------------------------------------------------------
[sigma] (2)                                                 [sigma v (p => tau)] (4)
----------- vI1                                            
sigma v tau                                                 
----------------------------------------------------------- vE (2,3)
                      sigma v tau
      ----------------------------------------- =>I (4)
        (sigma v (p => tau)) => (sigma v tau)
------------------------------------------------------- =>I (1)
  p => (sigma v (p => tau)) => (sigma v tau)
```

### Explicación y Análisis
- **Inducción en Implicaciones:** Cuando la propiedad a probar es una implicación `A => B`, la estrategia de demostración más limpia es "Asumo A y demuestro B". Si A es un booleano compuesto con `||`, aplicar lema de generación para analizar cada subcaso por separado es mandatorio para justificar matemáticamente.
- **Deducción Natural:** Para eliminar una disyunción (`vE`), debemos partir de la disyunción y abrir ramas donde asumimos cada lado temporalmente. Ambas ramas deben llegar a la misma conclusión.

## Ejercicio 3 - Cálculo Lambda Tipado

### Enunciado
Extensión para modelar listas ordenadas `[tau]<`.
El constructor `M1 ::< M2` agrega el elemento pero los observadores `head<` y `tail<` sacan el mínimo y el resto sin el mínimo, respectivamente.

### Resolución

**a) Reglas de Tipado**
```text
------------------------- T-VACIA
Gamma |- []< : [tau]<

Gamma |- M1 : tau    Gamma |- M2 : [tau]<
----------------------------------------- T-LISTA
Gamma |- M1 ::< M2 : [tau]<

Gamma |- M : [tau]<
---------------------- T-head
Gamma |- head<(M) : tau

Gamma |- M : [tau]<
---------------------- T-tail
Gamma |- tail<(M) : [tau]<
```

**b) Valores y Reducción**
Valores: `V ::= ... | []< | V ::< V`
Reglas de cómputo para `head<` (omitimos congruencia estándar):
```text
head<( V1 ::< []< ) -> V1
head<( V1 ::< V2 ::< V3 ) -> if (V1 < head(V2 ::< V3)) then V1 else head(V2 ::< V3)
```

Reglas de cómputo para `tail<`:
```text
tail<( V1 ::< []< ) -> []<
tail<( V1 ::< V2 ::< V3 ) -> if (V1 < head(V2 ::< V3)) then (V2 ::< V3) else V1 ::< tail(V2 ::< V3)
```

**c) Reducción paso a paso**
`head< ( ((\x:Nat. 2) zero) ::< 1 ::< []<Nat )`
1. Congruencia sobre el argumento de `head<`:
   `((\x:Nat. 2) zero) -> 2` (reducción Beta)
   Queda: `head< ( 2 ::< 1 ::< []<Nat )`
2. Cómputo sobre `head<` (lista de 2 elementos):
   `-> if 2 < head(1 ::< []<Nat) then 2 else head(1 ::< []<Nat)`
3. Cómputo auxiliar interno para `head(1 ::< []<Nat)`:
   `head(1 ::< []<Nat) -> 1`
4. Reemplazando:
   `if 2 < 1 then 2 else 1`
5. Evaluación de `if`:
   `if false then 2 else 1 -> 1`

### Explicación y Análisis
- **Listas con comportamiento Oculto:** Aunque la construcción con `::<` parece la clásica lista concatenada de derecha a izquierda, la semántica operacional de `head<` y `tail<` la convierte internamente en un "bag" (conjunto no ordenado) cuyos selectores se encargan de ordenarlo *on the fly* (evaluación). Las reglas recursivas de `head` y `tail` hacen esta búsqueda del mínimo en cada llamada.
