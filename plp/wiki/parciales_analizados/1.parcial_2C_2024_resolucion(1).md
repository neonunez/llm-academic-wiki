## Ejercicio 1 - Programación Funcional

### Enunciado
Se define el tipo `Buffer a` que permite escribir o leer en cualquiera de sus posiciones. Las posiciones tienen tipo `Int`. La lectura elimina el contenido leído.
```haskell
data Buffer a = Empty | Write Int a (Buffer a) | Read Int (Buffer a)
```
a) Dar el tipo y definir `foldBuffer` y `recBuffer`. (Solo aquí se permite recursión explícita).
b) Definir `posicionesOcupadas :: Buffer a -> [Int]` (sin posiciones repetidas).
c) Definir `contenido :: Int -> Buffer a -> Maybe a`, que devuelve el contenido si hay algo escrito en ella.
d) Definir `puedeCompletarLecturas :: Buffer a -> Bool`, que indica si cada lectura intenta acceder a algo que efectivamente fue escrito.
e) Definir `deshacer :: Buffer a -> Int -> Buffer a` usando evaluación parcial y currificación, que desactiva las últimas $n$ operaciones del buffer.

### Resolución
```haskell
-- a)
foldBuffer :: b -> (Int -> a -> b -> b) -> (Int -> b -> b) -> Buffer a -> b
foldBuffer cEmpty cWrite cRead t = case t of
  Empty -> cEmpty
  Write n x b -> cWrite n x (foldBuffer cEmpty cWrite cRead b)
  Read n b -> cRead n (foldBuffer cEmpty cWrite cRead b)

recBuffer :: b -> (Int -> a -> Buffer a -> b -> b) -> (Int -> Buffer a -> b -> b) -> Buffer a -> b
recBuffer cEmpty cWrite cRead t = case t of
  Empty -> cEmpty
  Write n x b -> cWrite n x b (recBuffer cEmpty cWrite cRead b)
  Read n b -> cRead n b (recBuffer cEmpty cWrite cRead b)

-- b)
posicionesOcupadas :: Buffer a -> [Int]
posicionesOcupadas = foldBuffer [] 
  (\n _ rec -> union [n] rec)
  (\n rec -> filter (not . (== n)) rec)

-- c)
contenido :: Int -> Buffer a -> Maybe a
contenido e = foldBuffer Nothing 
  (\n x rec -> if n == e then Just x else rec)
  (\n rec -> if n == e then Nothing else rec)

-- d)
puedeCompletarLecturas :: Buffer a -> Bool
puedeCompletarLecturas = recBuffer True 
  (\_ _ _ rec -> rec)
  (\n b rec -> elem n (posicionesOcupadas b) && rec)

-- e)
deshacer :: Buffer a -> Int -> Buffer a
deshacer = recBuffer (const Empty) 
  (\n x b rec -> \e -> if e == 0 then (Write n x b) else rec (e-1))
  (\n b rec -> \e -> if e == 0 then (Read n b) else rec (e-1))
```

### Explicación y Análisis
- **El tipo Buffer:** Modela un historial de operaciones en forma de AST (Árbol de Sintaxis Abstracta) linear, donde los nodos más arriba ("a la izquierda" en la sintaxis constructora) son operaciones más recientes.
- **`posicionesOcupadas`:** `fold` es ideal. Cada escritura agrega a la unión de conjuntos (para evitar repetidos se asume `union`), y cada lectura quita la posición de la ocupación (`filter`). 
- **`puedeCompletarLecturas`:** Usa `recBuffer` porque la lectura necesita acceder al "estado anterior del buffer" (argumento extra `b`) para computar las posiciones que estaban ocupadas hasta ese momento.
- **`deshacer`:** Esta función requiere truncar un número de constructores igual al argumento `e` proporcionado. Dado que recorremos la estructura con `rec`, la función de paso debe retornar *una función* `\e -> ...`. Si `e == 0`, se alcanzó el límite y reconstruimos de ahí en más (agregando la operación); si `e > 0`, se descarta el constructor actual y se delega el resto a `rec (e-1)`.

### Chuleta
- **Evaluación parcial con rec/fold:** Si debes consumir simultáneamente una estructura y un contador entero (ej: `drop`, `take`), que tu esquema devuelva una función `Int -> ...` y usa una abstracción lambda en el paso para administrar el conteo y la decisión.

## Ejercicio 2 - Demostración de Propiedades y Deducción Natural

### Enunciado a)
Demostrar por inducción en árboles: `forall t::AB a . forall u::AB a . altura t >= altura (zipAB t u)`
Lema provisto: `forall t::AB a . altura t >= 0`.

### Resolución a)
Inducción en `t`. `P(t) = forall u::AB a . altura t >= altura (zipAB t u)`

**Caso base `P(Nil)`:**
`altura Nil >= altura (zipAB Nil u)`
0 >= altura (const Nil u) = altura Nil = 0.
`0 >= 0` vale.

**Paso Inductivo `P(Bin i r d)`:**
HI: `P(i)` y `P(d)`.
`1 + max (altura i) (altura d) >= altura (zipAB (Bin i r d) u)`
Aplicamos extensionalidad estructural en `u`. Puede ser `Nil` o `Bin x y z`.
- *Subcaso `u = Nil`:*
  `zipAB (Bin i r d) Nil = Nil` por {Z1 + Beta}.
  `1 + max (altura i) (altura d) >= altura Nil = 0`.
  Como por lema las alturas de `i` y `d` son `>= 0`, su `max` es `>= 0`. Luego `1 + max >= 1 >= 0`. Vale.
- *Subcaso `u = Bin x y z`:*
  `zipAB (Bin i r d) (Bin x y z) = Bin (zipAB i x) (r,y) (zipAB d z)`
  El lado derecho es `1 + max (altura (zipAB i x)) (altura (zipAB d z))`.
  Debemos ver que `max (altura i) (altura d) >= max (altura (zipAB i x)) (altura (zipAB d z))`.
  Abrimos en dos escenarios por definición del máximo a la izquierda:
  - `max (altura i) (altura d) = altura i`:
    Sabemos que `altura i >= altura d`.
    Por HI en `i`, `altura i >= altura (zipAB i x)`.
    Por HI en `d` y la cota superior, `altura i >= altura d >= altura (zipAB d z)`.
    Como `altura i` es mayor o igual a ambos términos del segundo `max`, domina a dicho `max`.
  - El caso `max = altura d` es simétrico.
Demostrado.

### Explicación y Análisis
- **Extensionalidad:** Dado que hay dos árboles que condicionan el comportamiento, cuando hacemos inducción en uno (`t`), el caso recursivo se queda atascado si no "abrimos" el árbol libre (`u`) usando sus constructores posibles. Por eso la demostración se abre en los subcasos `Nil` y `Bin` de `u`.

### Enunciado b)

## Ejercicio 3 - Cálculo Lambda Tipado

### Enunciado
Extender el cálculo lambda tipado para árboles ternarios.
`AT(tau)` es el tipo del árbol. Un nodo tiene una raíz de tipo `tau` y 3 hijos (`M2`, `M3`, `M4`).

### Resolución

**a) Reglas de tipado**
```text
--------------------------------- (Ax AT)
Gamma |- TNil_tau : AT(tau)

Gamma |- M : tau   Gamma |- N : AT(tau)  Gamma |- O : AT(tau)  Gamma |- P : AT(tau)
--------------------------------------------------------------------------------- (Tern)
Gamma |- Tern(M,N,O,P) : AT(tau)

Gamma |- M : AT(tau)  
Gamma |- N : sigma   
Gamma, x:tau, ri:sigma, rm:sigma, rd:sigma |- O : sigma
---------------------------------------------------------------------------------------------------- (fold)
Gamma |- foldAT M |> TNil ~> N; Tern(x, ri, rm, rd) ~> O : sigma
```

**b) Semántica Operacional**
Valores: `V ::= ... | TNil_tau | Tern(V,V,V,V)`
Reglas de fold:
```text
foldAT TNil_tau |> TNil ~> N; Tern(x, ri, rm, rd) ~> O -> N   (e-cfN)

foldAT Tern(V1,V2,V3,V4) |> TNil ~> N; Tern(x, ri, rm, rd) ~> O -> 
  O{x:=V1, ri:=(foldAT V2 ...), rm:=(foldAT V3 ...), rd:=(foldAT V4 ...)}  (e-cfT)
```

**c) Reducción Paso a Paso**
```text
(\t:AT(Nat). foldAT t |> TNil ~> False; Tern(x,ri,rm,rd) ~> isZero(Pred(x))) Tern(1, TNil_Nat, TNil_Nat, TNil_Nat)
-> (Beta) foldAT Tern(1, TNil_Nat, TNil_Nat, TNil_Nat) |> TNil ~> False; Tern(...) ~> isZero(Pred(x))
-> (e-cfT) isZero(Pred(x)){x:=1, ri:=..., rm:=..., rd:=...}
-> isZero(Pred(1))
-> isZero(zero)
-> True
```

**d) Función mapAT**
```text
mapAT_sigma,tau = \f : sigma->tau . \t:AT(sigma) . 
   foldAT t |> TNil ~> TNil_tau ; 
                Tern(x, ri, rm, rd) ~> Tern(f x, ri, rm, rd)
```

### Explicación y Análisis
- **El paso `e-cfT` de un esquema estructural:** Como la recursión es provista desde el motor interno del esquema `fold`, la sustitución que se inyecta en el término recursivo `O` debe construir llamadas *completas* al `fold` para cada rama del árbol ternario (`V2`, `V3`, `V4`), ligando luego los resultados con las variables `ri`, `rm`, `rd`.
- **`map` con un `fold`:** El paso recursivo reconstruye un constructor del mismo tipo (`Tern`), invocando la función sobre la raíz y simplemente enlazando los hijos que ya vienen resueltos por el `fold` subyacente.
